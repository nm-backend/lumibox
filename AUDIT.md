## Что требует внешнего окружения

1. **Каталоги переводов (`.po`) не пересобраны.** `makemessages` требует GNU
   gettext, которого нет в текущем окружении (и Docker не запущен). Русские
   строки, добавленные в этой работе, в каталоги не попали: `ru` от этого не
   страдает (msgid и есть русский текст), а `en` и `ky` показывают для них
   русский — ровно то же поведение, что и у части интерфейса до работы.
   Команда для окружения с gettext:
   ```bash
   python manage.py makemessages -l en -l ky && python manage.py compilemessages
   ```
   Каталоги писались вручную (в них нет ссылок `#:`), поэтому перед первым
   `makemessages` стоит сделать копию: команда переразметит файлы целиком.

2. **Поиск на SQLite регистрозависим для кириллицы.** `icontains` уходит
   в `LIKE`, а он в SQLite регистронезависим только для латиницы: «начало»
   не найдёт «Начало». Бой и `docker-compose` работают на PostgreSQL (`ILIKE`),
   где всё верно. Касается только запуска через `run_local_windows.bat`.

3. **SMTP, Sentry, R2 и GA** включаются появлением своих переменных
   на хостинге, без правки кода. Точный список — в `.env.production.example`.

## Известные ограничения

- **Видео в R2 раздаётся публично** (`default_acl: "public-read"`): прямая
  ссылка открывается кем угодно, слоя доступа нет. Если появится платный
  доступ, это первое, что придётся закрыть.
- **Дубли CSS-правил** `.site-header`, `.search`, `.logo` (наслоение «скина»
  поверх базовой раскладки) не сведены: чистый рефактор без выгоды для зрителя,
  но с реальным риском регрессии вёрстки, которую нечем проверить автоматически.
- **Прогресс хранит одно место на запись**, а не отметки по каждой серии:
  показываем мы только «продолжить», а история «серия за серией» стоила бы
  записи на каждом таймкоде.
