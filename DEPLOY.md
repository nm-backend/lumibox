# Деплой LumiBox на постоянный сервер

Цель — сайт работает 24/7 и не зависит от вашего ноутбука. Ниже —
разворачивание на **Render** одним файлом-описанием (`render.yaml`).
Он поднимает сразу всё: web, фоновый воркер, PostgreSQL и Redis, выдаёт
HTTPS, следит за здоровьем и перезапускает упавшее.

> Что должен сделать **человек** (а не Claude): создать аккаунт, подтвердить
> оплату плана и, если нужен свой домен, купить его. Это ваш сервер, ваш
> биллинг и ваши учётные данные — код за вас их не заводит.

## Шаги

1. **Залейте проект на GitHub** (публичный или приватный репозиторий).
   ```bash
   git add -A && git commit -m "Deploy LumiBox" && git push
   ```

2. **Render → New → Blueprint** → выберите репозиторий. Render найдёт
   `render.yaml` и покажет, что создаст: `lumibox-web` и `lumibox-db`.

   Это бесплатный вариант: Redis в нём нет намеренно. Без `REDIS_URL` кэш
   работает в памяти процесса, а фоновые задачи выполняются прямо в запросе
   (`CELERY_TASK_ALWAYS_EAGER`), поэтому отдельный воркер не нужен.

   Нужен постоянно работающий сайт с Redis и воркером — переименуйте
   `render.paid.yaml` в `render.yaml` перед подключением Blueprint. Тогда
   Render создаст четыре сервиса: `lumibox-web`, `lumibox-worker`,
   `lumibox-db` и `lumibox-redis`, плюс диск на 1 ГБ под медиа.

3. **Заполните переменные** (помечены как «требует значения») и нажмите **Apply**:
   | Переменная | Значение |
   |---|---|
   | `DJANGO_SUPERUSER_EMAIL` | ваша почта для входа в админку |
   | `DJANGO_SUPERUSER_USERNAME` | имя администратора |
   | `DJANGO_SUPERUSER_PASSWORD` | надёжный пароль |
   | `DJANGO_ALLOWED_HOSTS` | пусто на старте; свой домен — позже |

   `DJANGO_SECRET_KEY` Render сгенерирует сам, базу и Redis подключит сам.

Через несколько минут сайт открыт на `https://lumibox-web.onrender.com`.
Миграции, демоданные и администратор создаются автоматически при первом деплое.

## Свой домен

Render → сервис `lumibox-web` → **Settings → Custom Domains** → добавьте домен
и пропишите у регистратора CNAME, который покажет Render. TLS-сертификат
Render выпустит автоматически. После этого впишите домен в `DJANGO_ALLOWED_HOSTS`.

## Что уже настроено за вас

- **HTTPS** и редирект с HTTP, HSTS, защищённые cookie — `config/settings/production.py`.
- **Автоперезапуск и health-check** — Render опрашивает `/healthz/` (проверяет
  базу и кэш) и перезапускает контейнер, если он молчит.
- **Постоянные данные** — PostgreSQL и Redis у Render персистентные; загруженные
  постеры лежат на подключённом диске (`/app/media`) и переживают выкат.
- **Статика** — собрана в образ и отдаётся WhiteNoise, отдельный CDN не нужен.
- **Логи** — идут в stdout, видны во вкладке Logs каждого сервиса.
- **Фоновые задачи** — воркер Celery со встроенным планировщиком (пересчёт рейтингов).

## Резервные копии

Render → `lumibox-db` → **Backups**: платные планы делают ежедневный бэкап
автоматически. Разовый дамп вручную:
```bash
pg_dump "$DATABASE_URL" > lumibox-$(date +%F).sql
```

## Честные ограничения

- **Бесплатные планы не дают 24/7.** Free-web засыпает после 15 минут тишины,
  free-Postgres живёт 30 дней. Для «всегда включено» нужен платный план
  (у Render это ~\$7/мес за сервис) — это решение и оплата за вами.
- **Медиа на одном диске.** Диск Render крепится к одному сервису и мешает
  бесшовному выкату нескольких реплик. Когда постеров и кадров станет много,
  вынесите медиа в объектное хранилище (S3 / Cloudflare R2 / Backblaze B2)
  через `django-storages` — настройки к этому уже готовы принять переменные.
- **Другие хостинги.** `render.yaml` заточен под Render, но образ обычный
  Docker — тот же `Dockerfile` разворачивается на Railway, Fly.io, Hetzner
  и т.п. Отличаются только способ задать переменные и подключить базу/Redis.
